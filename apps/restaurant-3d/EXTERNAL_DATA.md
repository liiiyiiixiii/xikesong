# 当前数据接入：demo-v1 与供餐业务模式

本文件以当前 `src/main.ts`、`src/live-state.ts` 和 `public/data/config.json` 为准。旧版 `mode: backend`、42 碗 lunch 接口、`mode: external` 与手工 restaurant-state.json 更新流程不适用于当前入口；它们属于 legacy 历史实现。

## 入口

- `/`：当前配置 `mode: demo-v1`，读取 `/api/demo/v1`。模拟午高峰为 96 道菜、174 盘、80 席，所有位置、顾客与动作来自已发布演示包。
- `/?mode=live`：供餐业务模式，读取同源 `GET /api/v2/session`、`GET /api/v2/kitchen/board` 和 `GET /api/v2/conveyor/state`。可把 config 的 mode 配为 live 作为默认。
- `/menu.html`：静态场景中的 96 道菜及满盘造型，不是实时业务菜单。
- `/plate-detail.html`：可拆卸碗的结构预览，不执行实际换盘操作。

## 供餐业务模式

登录通过 `POST /api/v2/session`，退出通过 DELETE。会话使用业务服务的 HttpOnly Cookie；前端不把凭证写进 localStorage、配置、URL 或日志。页面每秒读取会话、后厨聚合及轨道状态，并立即重试可见页面。没有登录时不读供餐数据。

只使用接口返回的有效绑定。scaleId、bindingId、dishId 原样保留，已校准时按服务器推算盘托位置显示在圆环示意中；圆环不是门店实测平面。未校准/过期的轨道按 positionOrder 与身份固定排列并明确提示未接入位置。这不是演示 plateId/slotId 映射。当前没有菜品外形映射，统一用中性余量柱显示可解释的 foodRemainingG/fullFoodG 比例，不借用演示菜品身份。可信零和未知分别显示；无有效观测不会显示成空盘。

供餐状态、处理建议、数据质量、余量百分比、时限与轨道位置依据由服务返回。正常盘默认不显示标签，点击仅显示菜名；补菜/空盘自动黄/红提示，临近时限/超时自动黄/红提示，超时优先。标签跟随、避让、不弹模态框。客户端不重新按阈值分类。断网、格式错误、环境冲突或超过五秒未成功读取时，当前余量和区域标未知；轨道还受服务器 validUntil 的单独有效期限制。认证失效会清除已有业务实体。

页面校验正式 ServingView schema，并拒绝重复设备/绑定、会话环境不一致、依据时间晚于服务器时间以及倒退快照。test/demo/live 环境明确显示；live 环境名字本身不证明传感器或现场流程已经验收。

没有顾客、员工轨迹或实际坐标时不生成这些内容。普通补菜由后端识别；例外登记及任务详情在业务工作台处理，本页仅提供状态查看与跳转。

## 本地代理与部署

默认主服务为 http://127.0.0.1:5173。开发和预览代理 `/api/v2`、`/api/demo`、`/api/restaurant`。独立验收可用：

```sh
OPERATIONS_API_TARGET=http://127.0.0.1:5183 npm run dev -- --port 4183
```

这只改变 v2 代理目标；共享演示仍指向原主服务。业务工作台链接随显式代理目标变化，也可通过 `config.operationsUrl` 配置。

正式静态部署必须提供同源 `/api/v2` 与演示 API 反向代理，并配置业务工作台地址，不能保留本机地址。不得在前端配置中保存设备或工作站凭证。

## 验证范围

`tests/live-state.test.ts` 覆盖身份、环境、会话、可信零/未知、断网/重连、快照拒收、登录退出和并发轮询；使用测试替身，不写业务数据。`tests/state.test.ts` 覆盖演示共享时钟与事件质量。正式场景几何与演示包仍由原有严格测试验证。

`scripts/verify-live.ts` 验证运行中的 demo-v1 HTTP，会暂停/重播共享演示并写报告；它不验证硬件，也不是无副作用检查。


后厨入口：业务 `/operations/kitchen`，演示 `/operations/kitchen?mode=demo`，均支持 `windowId` 独立开屏。演示屏按演示几何后厨入口排序，业务屏只读配置好的真实轨道；两者不混用位置或身份。演示时限为明确标注的 4 分钟提醒/6 分钟超时；真实阈值需管理配置，补菜不会重置时限。

本轮接口契约 `2.0.0-dev.5`。浏览器验收分别覆盖独立 test 数据库真实 HTTP 和受控演示显示场景；均不能替代现场传感器与轨道验收。


## 逐盘批次与场景告警（2026-10-14）

演示时限读取数据包 `servingBatches`，按 `plateId`、`batchId`、`startedAtMs`、`endedAtMs` 及批次时限快照计算。时间相对播放起点，负数表示开播前已上台；区间为左闭右开。撤批次结束计时，新批次重新计时；普通补菜、重量变化和断线重连不重置时间。旧包缺少批次时返回未登记，不从零开始计时。后端验证未知餐盘、重复批次、区间重叠和非法时限。

当前96个营业盘的开餐批次由仿真生成器显式登记：按供餐口经过时刻与分轮备餐计划生成开播前的上台时间，保留原重量、顾客与补菜事件；不是从现实设备推断的记录。批次演示参数为上台20分钟提醒、30分钟超时，仅供演示，不作为任何食品的安全时限；实际营业使用业务环境配置的规则。备用轨道78盘不产生时限、补菜提醒或后厨待办，选中时显示“备用 · 未供餐”。

3D普通提醒仅为盘边小标记。只自动展开空盘/超时等紧急提醒，连同选中盘最多3张卡片，选中盘优先；其余计数汇总，后厨屏保留完整业务列表。放大视角不会增加卡片上限。新数据包身份变化会开启新的演示会话。
