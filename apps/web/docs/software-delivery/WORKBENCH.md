# 业务工作台使用说明

首页的“业务工作台”打开 `/operations`。演示、原有实时页、画像和备料仍保留各自入口。工作台使用 `operations-v2 / 2.0.0-dev.4` 契约和实际服务；没有可用接口时显示错误，不自动切换示例数据。

## 登录和配置

使用管理员分配的员工或管理工作站凭证登录，确认页头的身份与环境。凭证不会写入浏览器本地存储，会话由 HttpOnly Cookie 管理。管理者可在“设置与诊断”登记设备、初始菜品绑定、计量参数、供餐规则和更换时限。参数应来自门店实际确认，未配置项保持未知。已有绑定的菜品、皮重、满量改变应通过“换盘”登记。

凭证管理支持员工、管理者和设备凭证。新凭证只在生成后显示一次；安全保存后隐藏。设备凭证必须指定允许上报的秤位。离开共享工作站时退出登录。

“设置与诊断”还显示最后调度、失败码、重算积压、待核实轮次和未关闭任务。原始样本清理默认关闭；管理者可以设置24–8760小时保留期并明确启用。活动绑定和业务依据始终受保护，不能把保留期理解为所有样本的删除期限。策略及执行进度在刷新和服务重启后保留。

## 实时、后厨和前厅

三页共用实际任务和碗位数据，后厨与前厅默认按责任区域筛选。位置未知会明确标注，列表排列不代表实物位置。当前数据过期、设备离线或重量未知时不会显示为零；可打开碗位详情查看最后确认重量及时间。

任务按钮只提供后端当前允许的动作。接手、暂缓、交接和取消都需要服务端确认；暂缓上限由该菜品规则决定。“报告完成”会进入等待核验，不能等同于补菜完成；具备允许动作和核实依据时，可提交人工核实。任务详情保留人工与自动处理历史。另一工作站先更新导致冲突时，页面刷新当前版本，员工核对后再提交。

补菜和更换时限提示音需分别主动开启，并按记录状态去重。页面关闭时没有浏览器提示音，也不提供后台推送保证。

## 操作、轮次和修正

选择具体碗位后，可以登记补菜、加冰、排水、部分撤菜、整盘撤下、换盘，以及人工出入后厨边界。无法确认的重量选择“未知”；填入实测量并不自行变为已核验。

“读取前后称重依据”查询操作时间前后各五分钟的真实原始读数。选择前、后各一条有效样本，服务端按配置窗口核对时间与质量平衡。缺少读数或不匹配时保留待核实状态。人工输入依据编号也保留。请求失败可使用“重试同一请求”，它保留原请求编号和原内容；编辑内容后会生成新请求。

碗位详情和报表下方的“操作记录”可按北京时间日期及绑定编号找回任何登记，包括未形成轮次的补菜和加冰；原记录与更正记录均保留，只有当前有效版本可以继续更正。碗位详情及报表菜品明细还可打开轮次，查看出入重量、操作、质量原因和修订历史。管理者可以记录轮次核实结论。“更正此操作”基于原操作和版本新增更正记录，再重算受影响统计；原记录仍可追溯。已撤盘或换盘记录的更正不会再次关闭或创建绑定。

## 更换时限和撤下记录

“时限与报损”可为尚未计时的具体碗登记上台批次，开始时间必须属于该绑定有效期。每批保存当时的时限规则，修改规则不会重置已有批次。部分撤下保留原批次；整盘撤下或换盘通过同一个业务提交关闭原批次，避免重复记账。

撤下记录区分报损与保留、已知与未知重量，并显示被更正的旧版本。仅当前有效记录参与统计；未知重量不会按零处理。

## 报表与原有画像

报表支持单日、近十五天、近三十天、完整自然月和一至三十一天自定义范围，日期按北京时间。新轮次口径按回后厨完成日期归属。v2 接口保留旧观测下降口径选项，但当前服务尚未提供该口径，选择时会明确报错；已有旧差分统计请从“原有备料与报损”入口查看。权威合计、排名、覆盖和缺菜分钟由服务器返回。修改筛选后先查询，再下载同一数据版本 CSV；后台数据变化导致冲突时刷新再导出。

原有客群画像继续使用旧差分账本，并显示来源、算法版本、截止时间和快照校验结果。算法名称中的版本字符不代表已切换到新轮次账本。依据改变时保留原画像和已确认备料，明确提示过期，不自动改写历史确认结果。

“下载同版本 AI 依据”导出与当前报表相同数据版本和查询时刻的 JSON，只提供只读证据，不调用外部模型，也不加入旧模型训练。分页、CSV 和 AI 依据都固定查询时刻；业务数据变化后需重新查询。

原有每日画像中的“查看画像档案与版本”可查看旧档案及其过期状态。“按当前依据保存新版本”以原截止时点重新生成数值档案，保留旧版本；通过版本选择器可切回查看。该动作不生成 AI 解读，也不覆盖已确认备料计划。

## 验证方式

`tests/operations-ui-smoke.mjs` 使用显式 schema fixture，覆盖错误、冲突、慢请求、未知值、权限、声音去重、称重依据、更正和移动视口；它只证明前端交互。

`tests/operations-http-ui-smoke.mjs` 要求显式的本地 `environment=test` 连接文件，通过真实 HTTP、浏览器会话和独立持久化数据库验证任务争抢、流转、操作、导出、配置与时限报损。脚本不使用路由 mock，也不写旧业务接口。`tests/operations-evidence-http-ui-smoke.mjs` 进一步通过真实读数选择、更正原操作和刷新重算验证闭环。`tests/operations-history-http-ui-smoke.mjs` 验证未进入轮次的登记在刷新后可找回并更正，原记录保留且只有有效版本可继续更正。`tests/operations-system-http-ui-smoke.mjs` 验证运行诊断、保留策略持久化和 AI 依据下载。服务和测试结果由交付记录说明；这类测试不等于真实传感器、餐盘与门店现场验收。


## 2026-10-13：后厨十盘屏与自动补菜

入口 `/operations/kitchen`；演示入口 `/operations/kitchen?mode=demo`。窗口选择保存在 `windowId` 查询参数中，可分别开屏。桌面两排五张，少于十盘按实际数量显示；按到入口距离排序，告警不改变顺序。未知余量为“待核实”，估计值带“约”，卡片不显示克数。已进后厨的异常盘独立列出。

普通补菜无需接手任务、填写操作编号或逐盘确认。系统关联进入/离开后厨的稳定读数、相同绑定、连续设备状态；无例外且净增重超过配置容差才推断补菜。补后仍低量不完成任务；无增重不记补菜。加冰等例外可多选快捷登记，逐盘保存回执，失败重试复用原 requestId。单盘详细表单保留换盘目标菜品、容器与版本确认，并可查看自动识别依据及历史修订。

补菜不会重置时限；含冰或组成不明时不以总重量充当食物余量。迟到登记、更正或原始依据补传触发重算，可能使之前的自动完成回到待核实。拿盘造成低于皮重或缺测的处理段保守进入待核实。

管理页“轨道与后厨识别”配置真实轨道长度、方向、盘托偏移、入口出口和心跳有效期。生产默认无轨道且不开启自动识别。固定盘托/秤位不变，取碗后放回原位；盘托实际移位必须停机重新校准。业务 3D 使用服务器位置的圆环示意，明确标注非门店实测平面；未接入位置时只显示固定排列，不借演示轨道替代。

演示与业务共用提示规则：正常盘点击仅显示菜名；少量黄色、空盘红色；临近时限黄色、超时红色。超时优先“已超时，请更换”。标签跟随餐盘、避让、不抢焦点；显示空间不足时列出隐藏提示数量。演示计时明确使用 4 分钟提醒/6 分钟到期，仅是演示规则。

验收脚本：`tests/operations-kitchen.test.ts`（推断、失效重算、定位及备份），`tests/kitchen-screen-http-ui-smoke.mjs`（独立测试库实际 HTTP/D1/浏览器），`tests/kitchen-3d-ui-smoke.mjs`（受控演示浏览器场景）。浏览器脚本使用 PLAYWRIGHT_MODULE、PLAYWRIGHT_EXECUTABLE_PATH；实际 HTTP 脚本额外要求 OPERATIONS_TEST_CREDENTIALS_FILE 指向 environment=test 的本地连接文件。脚本内的尺寸、速度、称重阈值只用于测试。

本轮没有生产发布，也没有真实硬件验收。现场仍需提供真实轨道参数、称重采样周期、稳定容差、边界事件来源、盘托映射及校准基准。
