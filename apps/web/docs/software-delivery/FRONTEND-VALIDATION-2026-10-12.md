# 工作台前端验证记录 · 2026-10-12

契约：`operations-v2 / 2.0.0-dev.4`，32 个业务端点及独立 session 接口。实际页面不导入测试 fixture。使用说明见 [WORKBENCH.md](WORKBENCH.md)。

## 页面交付

| 页面 | 已接实际服务的功能 |
| --- | --- |
| `/operations?view=live` | 后端供餐状态、建议、全部质量状态、最后有效重量和位置依据、任务、两类独立提醒 |
| `/operations?view=kitchen` | 后厨责任任务，接手、暂缓、交接、报告完成、核实和取消；具体碗位操作 |
| `/operations?view=front` | 前厅责任任务及同等任务工作流，不是只读展示 |
| `/operations?view=reports` | 单日、近15/30天、自然月、自定义范围；口径区分、覆盖与缺菜、多碗合并结果、轮次依据、同版本及查询时刻的 CSV 与 AI 只读依据 |
| `/operations?view=freshness` | 上台批次、快照时限、部分撤下保留、整盘撤下/换盘事务、报损与更正历史 |
| `/operations?view=settings` | 管理权限、供餐规则、时限规则、设备和初始绑定、计量参数、设备与后台调度诊断、保留策略、凭证发放及撤销 |

操作表单支持六类事件、未知量、稳定 requestId 重试、绑定版本检查、真实称重依据选取。操作记录按日期及绑定查询，可找回未形成轮次的操作，只有有效版本可以更正；轮次详情也可更正原操作；已闭合盘的历史字段保持不变。员工登录 token 不落本地存储。首页保留演示和旧业务，并新增明确工作台入口。

旧每日画像改为以服务端 `asOf` 默认选日，修复数据截止10月5日却读取机器10月12日的问题。每日与档案显示旧差分来源、算法和快照是否过期。旧 UI smoke 的模式入口、过时组件断言和宽泛成功 mock 已纠正；未知 API 请求会使测试失败。
