## 1 工期如何缩短而不删功能

1. 直接扩展当前系统。复用已有 React 页面、D1 访问方式、称重保护、时限事务、统计查询及测试；不新建框架、不重做品牌视觉、不改用陌生数据库。
2. 以同一份可执行契约拆分工作。前端、计量和任务并行开发，接口、表结构、事务和文件归属由主集成统一维护，减少互相等待与返工。
3. 测试随代码推进。每个模块提交可运行的实现和验证结果，第 2 小时就接通真实接口，第 4.5 小时前覆盖全功能，不能到最后才首次启动。
4. 复用脚本完成验证和交接。请求样例、schema、mock、客户端和测试使用同一来源；复用已有回放器生成测试输入，减少人工重复整理。
5. 三名团队成员保持原责任：硬件同学独立工作；软件成员 A 核对员工操作与页面，软件成员 B 核对计量、数据和协议。Codex 承担实现，主集成负责四条执行流合并与证据核对。

不会通过以下方式减少工作：把持久化改为内存数组、把正式页面替换为静态演示、删除异常场景、让后端返回固定成功、跳过权限与数据隔离、将测试推迟到交付以后。AI 并行执行会消耗额外推理额度，不能将工期缩短直接解释为费用必然同比下降。

## 6 提前固定的集成接口

0:45 前由主集成固定以下约定，四流随后按版本开发：

- 所有请求和响应以 `lib/contracts/operations-v2.ts` 为公共入口，Zod schema 与运行时一致。类型缺口由主集成集中修订，不能各流私有扩展同名字段。
- 凭证解析产生可信调用方上下文，服务函数不接收客户端自报的权限。当前 501 骨架接上认证和真实服务后才对有效操作返回成功。
- 数据写入使用当前 SQLite／D1 批处理和版本条件的可靠事务方式。数据服务返回 operationId、影响轮次和结果版本，业务服务读取约定投影；不传递跨模块数据库事务半成品。
- 账本是正式取用唯一来源；连续下降是实时观测，二者不相加。报表、CSV 和 AI 读取同一结果版本。
- 单次撤菜／换盘只调用一个应用服务，复用现有时限事务规则；业务流程不能另写一次报损。
- 后台任务函数由业务流提供，租约、调度入口和启动方式由主集成装配；页面关闭不影响任务到期和重算。
- 契约 fixture 必须通过 schema，但不能作为真实接口成功响应；主流程完成后浏览器测试改连真实测试实例。

## 7 隔离运行和验证方式

当前本地启动通常使用 5173 端口及 `.wrangler/state`，旧接口 smoke 会写入指定实例。第一步必须分配单独端口、单独持久化目录、单独凭证；测试脚本显式传入测试地址，不默认触碰现有经营库。

测试同时覆盖三层：纯规则与契约测试、真实 SQLite／D1 事务及 HTTP 回放、浏览器操作与持久化验证。当前 `npm test` 只匹配 `tests/*.test.ts`，新增目录测试必须接入明确命令，不能仅放置测试文件便声称已运行。

以原方案 T01—T16 为完整验收清单。至少输出以下结果：

| 验证范围 | 验证方法 | 必须留存的证据 |
| --- | --- | --- |
| 接口与计量 | 真值外置的样本／边界／操作经正式 HTTP 写入，再查询账本 | 每轮预期、实际、差异、质量和唯一记账次数 |
| 幂等与冲突 | 重复报文、同号异内容、两个调用方同时接单／完成 | 唯一有效写入、409 冲突和无重复影响 |
| 非食物与异常 | 加冰排水、未知量、撤菜、断线、换盘、迟到边界 | 不能自动归为可信取用的场景确实保留待核实 |
| 页面和任务 | 两个浏览器接手、交接、暂缓、报告完成、等待核验 | 真实后端状态、刷新后仍存在及错误提示 |
| 报表与修正 | 更正历史分类、跨日跨月、多碗缺菜、CSV 导出 | 账本／日／区间／CSV 同版本一致 |
| 运行和兼容 | 重启、作业中断恢复、迁移、备份恢复、旧有功能回归 | 恢复记录、版本和失败修复结果 |
| 交付产物 | TypeScript、lint、生产构建、最终产物启动 | 命令、退出码、构建版本和关键流程结果 |

分钟和日期跨度可用受控时钟与快速回放验证，不需要为每个业务时段等待实际时间；但这种方法不能证明真实运行了一个月、传感器精度或现场整班稳定。持续上传性能可以在最后集成阶段同步测量，报告实际持续时长与样本数量。

## 8 时间控制和故障处理

主集成每 30 分钟维护 D01—D14 状态：未开始、实现中、已接入、验证通过、存在失败。同步范围和数据，不要求每个流停下来写长报告。

G2 未贯通时，优先把接入、持久化、业务服务和页面的断点修通，其余执行流继续完成独立范围。G3 出现遗漏时立即重分配已完成流，不能把遗漏移到所谓第二期。G4 后停止无关重构与非需求装饰，全部能力仍必须达到原验收；测试失败优先处理。

重大问题包括错误记账、重复报损、越权写入、无法恢复、核心页面无法操作或用 mock 代替实际服务。这些问题没有通过测试前不能交付为“完整”。到第 6 小时若仍存在未完成项，记录精确剩余项和失败证据，不能篡改通过标准或悄悄删除范围。

开发只在需求明确的功能内自主决策；阈值等企业未确认值保留配置入口与未配置提示。开发不停下来等待硬件到货或询问常规实现选择，接口先由模拟客户端联调。
