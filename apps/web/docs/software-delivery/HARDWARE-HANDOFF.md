# 红考拉硬件与软件对接清单

更新日期：2026 年 10 月 12 日。状态：v2 软件协议及持久化服务已实现，本机隔离软件联调已验证，真实硬件尚待现场验收。硬件同学负责设备实现；软件后端负责人负责协议、测试地址、设备登记、凭证发放和接收诊断。本文不要求特定芯片、传感器、安装或通信硬件方案。

当前共享契约版本为 `operations-v2 / 2.0.0-dev.4`，业务注册表有 32 个端点，另有工作站会话。运行实例需要配置 `OPS_DB`、明确的 `OPS_V2_ENVIRONMENT` 与凭证；未配置／暂不可用返回 503，已配置但未认证返回 401。交付记录分别标注软件接口回放与真实设备联调，不互相替代。

完整报文字段、回执和错误码见 [共同接口契约](INTERFACE.md)。旧协议见 [现有接入说明](../INTEGRATION.md)。本文确认代码与软件测试能力，不表示外部测试域名已部署或真实设备已登记；具体可用实例由软件负责人交接。

原始波形保留窗口默认 24 小时，清理需管理者明确启用；当前绑定、待核实记录和账本依据优先保护。波形清理后保留设备身份哈希，重传同一 bootId／sequence 不会重新创建已清理的样本或覆盖历史身份。该窗口不同于实时上传允许的 24 小时最大延迟，扩大保留窗口不会自动放宽协议上传限制。管理诊断提供清理结果及持久化作业失败、积压、最后调度状态。

## 3 上报必须遵守的规则

1. 使用克作为单位，上报毛重；不自行扣除软件配置皮重后仍命名为 grossG。
2. 每次真实启动使用新的 bootId；同次启动的样本 sequence 递增。网络重试保留原 ID、原时间、原数值。
3. 采样时间是实际采样时刻，重传不改为当前时刻；收到服务器时间错误时修正后续时钟，不篡改原样本冒充新数据。
4. 无效读数不能上报为零。v2 用 measurementStatus 和 null；旧协议仅上传有效重量，软件根据缺测判定未知。
5. 相同样本身份不能携带不同重量。冲突需排查上报逻辑，不能靠换一个随机 ID 重复记账。
6. 重量批量请求可能部分成功，必须逐项检查回执。超时结果未知时复用原批次重试；401／403、字段错误、设备未配置等按原因处理，避免无限重试；管理令牌不能代替设备令牌。
7. 出口和入口使用统一定义：exit_kitchen 为离开后厨进入顾客区；enter_kitchen 为从顾客区返回后厨。事件可重传，但不能重复生成新 eventId 表示同一次经过。
8. 不上传菜品销量、食物余量、补菜状态或顾客夹取次数作为已知事实；这些由软件根据可用信息处理。

## 4 软件工具的使用

先从软件负责人获取专用测试实例地址、登记好的 scaleId、其绑定与计量参数，以及仅限这些设备的 device 凭证。测试和真实实例隔离；令牌通过私有渠道发放，禁止放入 URL、JSONL、公共文档或日志。

只读认证检查不会生成或发送样本：

```sh
node --experimental-strip-types scripts/probe-hardware-contracts.ts --base https://测试实例域名
```

探针只 GET serving/state 和 devices/diagnostics，不携带凭证。401 表示存在认证保护；503 表示尚未配置或暂不可用。这两种返回均不是设备接入成功证明；其他返回使探针失败。

`raw.jsonl` 每一行是完整的 v2 `samples` 或 `events` envelope，字段见共同契约。由设备的原始记录填写 batchId、bootId、sequence、sampledAt／occurredAt、grossG 和状态；同一凭证的样本批次和事件批次必须使用各自不同的 batchId。工具不生成这些值，不修改采样时刻，不接受 expected／truth／销量等额外字段。每批样本最多 1000 条，事件最多 100 条，分别限制 1 MB 和 256 KB。

```sh
# 仅校验：不会读凭证或发网络请求
node --experimental-strip-types scripts/send-hardware-jsonl.ts --validate-only --input ./raw.jsonl

# DEVICE_TOKEN 必须已通过私有凭证渠道注入当前环境；此处只传变量名
node --experimental-strip-types scripts/send-hardware-jsonl.ts --base https://测试实例域名 --token-env DEVICE_TOKEN --input ./raw.jsonl --max-attempts 3

# 也可使用仅当前用户可读、内容只有令牌的私有文件
node --experimental-strip-types scripts/send-hardware-jsonl.ts --base https://测试实例域名 --token-file /私有路径/device-token --input ./raw.jsonl
```

发送必须显式提供 base、token-env 或 token-file、input；没有默认地址或默认凭证，不支持在命令参数中直接放令牌。外部地址只接受 HTTPS，本机 localhost／127.0.0.1／::1 可以使用 HTTP。工具先严格校验整个输入文件，再顺序发送，不自动跟随重定向。

网络超时结果未知、已知 429／503 及逐项 BUSY 可有限重试，始终复用同一批次和原内容。默认最多 3 次，可设置 1—5 次；单次请求默认 10 秒，可用 timeout-ms 设置 100—60000 毫秒。遵守服务端 Retry-After，要求等待超过 60 秒时停止，由对接人员稍后用原文件重试。401／403、未知错误、身份不匹配或无效回执立即停止。任一批仍有拒绝、忽略或未知结果时不继续后续批次，退出码为 1；所有项 accepted／duplicate 才为 0。

标准输出逐行记录批次、尝试次数、每项身份、code／status／retryable，以及事件 processingStatus。`waiting_sample` 只表示事件已保存但缺少关联样本；`applied` 也不等于取用轮次已确认。请求成功不能取代业务及硬件验收。工具不会输出凭证。将逐项回执与原始 JSONL 一起留存，严禁因失败重新随机生成身份。

软件工具测试：`node --experimental-strip-types --test tests/hardware-client.test.ts`。本机隔离实例验证过真实 HTTP 回执与原批重试，但输入仍是软件测试观测，不是真实设备数据。

## 5 联调执行顺序

| 步骤 | 输入 | 通过标准 |
| --- | --- | --- |
| H01 连接与身份 | 有效及无效凭证、已登记和未登记设备 | 回执清楚，不接受越权设备 |
| H02 正常重量 | 连续有效样本 | 诊断页时间与重量一致，能追溯原始报文 |
| H03 网络重试 | 同一样本重复十次，同 ID 异内容一次 | 只保存一份有效业务依据；异内容明确冲突 |
| H04 乱序与重启 | 旧序号、旧 bootId、新 bootId | 最新状态不回退；重启后重新建立基线 |
| H05 缺测与故障 | 中断上报、故障读数、恢复 | 显示未知／异常；恢复差值不自动记取用 |
| H06 时间异常 | 无时区、超前、过旧、延迟重传 | 与契约一致的拒绝或迟到处理 |
| H07 进出后厨 | 出口、入口及读数引用 | 正确关联同一设备轮次，可查看证据 |
| H08 异常边界 | 重复出口、先收到入口、引用样本迟到 | 不错误配对；保留 waiting_sample 或 pending_review |
| H09 多设备批量 | 实际设备数量的持续上传 | 每项有回执，设备之间不串号，记录吞吐及延迟 |

H01—H06 可以只使用重量协议先完成；H07—H08 依赖边界能力。H09 的数量以实际配置为准，当前演示的 42 个点位不是企业已确认的硬件数量。

## 6 联调结果记录

每轮保存协议版本、软件提交版本、设备版本、设备编号、测试时间、请求编号或样本身份、预期、实际回执、是否通过、问题责任人与复测结果。原始报文需脱敏。

接口接收成功只证明数据已送达，业务精度由软件计量与现场流程另行验收。重量、边界或操作缺失时软件应保留质量限制，不由接口返回 success 推断取用已准确。

现场 H01—H09 当前均未记录真实硬件验收通过。采样周期、噪声／漂移、时钟同步、安装影响、边界传感器可用性、断网缓存容量和持续多设备吞吐，必须以实测配置和记录交付。3D 的固定排列与软件回放不构成实际位置证明。


## 后厨十盘接口接入补充

先在管理页录入真实轨道和盘托映射，给网关凭证授权 `trackIds`；仅有 `scaleIds` 不允许写轨道遥测。上报 `/api/v2/telemetry/conveyor` 的 motion（trackId、bootId、连续 sequence、occurredAt、running、speedMps、direction），停止状态持续心跳，校准时确认零位。轨道与称重使用独立授权范围。现有称重 JSONL 工具保持原样；轨道心跳直接按共享 `motionRequestSchema` 对接。缺少现场尺寸/基准时不得把演示配置复制为生产值。

自动补菜必须另有真实 `enter_kitchen` / `exit_kitchen` 事件及 sampleRef；需要前后稳定样本、连续称重、同一绑定、没有加冰排水等例外。推算轨道位置不是边界证据。固件重启换 bootId；异常盘托移动或方向改变后停机校准。拿碗再放回保持同一秤位，改变菜品/容器通过换绑确认。

发现盘托移位/基准丢失时，网关上报 `motion.positionValid=false`，服务器立即锁定重新校准状态。恢复有效且静止的心跳后仍需管理校准；单纯恢复心跳不会自动相信盘序。没有移位传感器时必须由现场停机检查与重新校准，软件不能凭速度心跳发现机械移位。
