## 页面行为

厨房首页优先展示紧急与待处理任务，再显示全部碗位。碗位卡片应包含菜名、碗位编号、四档供餐状态、补菜建议和质量提示。克数和百分比作为辅助信息；供应状态未知时不使用正常状态的颜色或文案。

任务按钮遵循后端返回的 `allowedActions`。接手前不假设成功；收到版本冲突后刷新任务。完成操作可能进入 `verifying`，此时显示等待核验，不能提前显示已完成。暂缓期间仍显示真实余量。区域未知时不标成后厨。

请求失败时保留最后成功数据，但明确标记过期及最后成功时间；禁止失败后回退到演示数据。轮询使用请求序号或取消机制，避免慢的旧响应覆盖新的结果。不要让一个页面错误导致所有任务看起来已清空。

提醒声音需要员工主动开启。缺菜提醒与时限提醒有不同标签，按任务编号和状态版本去重；明确说明页面关闭时是否仍有提醒能力。首版如未实现后台推送，就不承诺关闭页面仍可通知。

人工操作字段由契约定义。换盘和撤菜需复用或整合现有时限流程，提交一次只产生一组业务记录，不能同时调用旧、新接口重复记账。具体由 B 提供事务入口。

报表支持日期、最近十五天、最近三十天和自然月；最近 N 天含所选结束日。自然半月如尚未确定，界面不以“半月”代替“近十五天”。按后端的排名展示，权威合计不在浏览器重算。

## Mock 和测试

开发 mock 仅用于本地页面或浏览器测试，可放 `tests/ui/fixtures/`。共享字段和值由 B01 提供，A 可组合页面场景，不得添加后端没有的业务结果字段。

至少验证：四档状态；所有数据质量状态；未知重量；同菜多盘；长菜名；请求慢和失败；空列表；双浏览器争抢任务；重复点击；暂缓到期；完成等待核验；报表没有有效数据；操作后刷新；厨房大屏和管理端常用视口。检查字体、按钮和重点任务无需滚动即可识别的程度。

运行受影响的现有前端测试，以及项目的 TypeScript 检查、lint 和构建。记录既有失败与本次引入失败的区别。后端未交付时可以标记“mock 验证通过”，不能写成“联调通过”。
