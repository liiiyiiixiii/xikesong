# 可视化客群画像

## 页面与周期

首页仅展示当前选中的一张紧凑自然周卡片，默认本周，通过上一周／下一周按钮每次切换一周；本周禁用下一周。点击后进入周详情，默认整周，可切换周一至周日。所有日期按北京时间，未来日期禁用，未完结周期明确标注。日期卡片与整周名称不使用第一名菜品命名画像。

详情依次展示菜品取用矩形树图、时段柱状图、占比变化方向条形图、自动 AI 解读，以及唯一一张全部菜品明细表。矩形树图按具体菜品编号计算面积，不合并同类或同名菜，不截取前几名。小块可搜索定位；零取用与缺失不分配虚假面积，提供独立状态入口。

点击时段切换树图到该时段的全部已观测菜品；点击图中的菜品展开并定位明细行。明细统一包含当期数值、样本、上一周期变化与分析摘要；每日、时段、连续四周数据及建议在同一行内部展开，不重复创建多张菜品表。

## 分析口径

- 有效重量占比使用完整、供应充足且无缺菜的菜品日记录，未知值不进入分母。零分母留空；已观测重量可能包含供应受限记录。
- 群体画像描述取用构成、时段差异和周期变化，不用第一名或虚构评分代替群体画像。所有比例都是重量占比，不是顾客人数、人口属性或喜爱评分。
- 周变化按同星期、共同有效菜品比较，每道菜至少三个配对日期且两侧总量非零；日变化按前一天的共同有效菜品比较。不可比较的菜保留原因，缺失不当作零。
- 时段为上午00–11、午餐11–14、下午14–17、晚餐17–21、夜间21–24，分母为各时段已观测重量。无分钟记录不从全天推算，也不把取用峰值当作客流峰值。
- 供菜建议需由管理者确认，相关变化不解释为因果。

## 自动解读

进入详情或切换日期后先展示图表，有取用数据且模型已连接时自动生成综合解读。首段简短呈现，全文与证据折叠，补充问题为次要操作。模型未连接、失败、无数据时分别显示状态，不用固定话术冒充模型输出。

同一页面会话内按日期范围、模型连接版本、模型名称及实际统计内容缓存，最多十二份、三十分钟有效。仅查询时间戳变化不重复调用；刷新数据不强制重新分析，手动“重新分析”跳过缓存。范围或数据切换取消旧请求，检查返回范围并阻止旧结果串入新范围。缓存只在内存，不写数据库或浏览器持久存储。

## 接口

沿用 `GET /api/intelligence/portrait?week=YYYY-MM-DD` 和 `POST /api/intelligence`，不新增公共接口或迁移。`weekly_portrait` 提供自然周及参考周期的实际统计，模型对指定日与背景周作区分，引用具体菜品为证据，不重复列举全部菜品数值。

## 页面内连接 DeepSeek

最下方填写 API Key，点击“连接并保存”。服务端先发送一条不含业务数据的简短模型测试，成功后才保存；失败不覆盖原配置。模型名称默认 `deepseek-flash`，可在高级设置更改。支持测试当前连接、更换密钥、断开并移除。

`GET /api/intelligence/config` 只返回连接状态、模型、尾号和来源。`POST` 支持 `connect`（`apiKey`、可选 `model`）、`test`、`disconnect`；同源校验和字段校验先于任何服务调用。页面输入只保留在组件内存中，成功后清空，不写 localStorage。

保存位置为已有 `model_credentials` 表中的独立 `intelligence-v1` 记录，不恢复读取历史版本凭证。API Key 与模型名经 AES-GCM 加密，加密主密钥为服务端 `ANALYSIS_KEY_SECRET`。本地 `npm run dev/start` 首次自动生成并保存在忽略提交、权限0600的 `.env`，之后保持不变；备份数据库时需同时安全保留该主密钥，否则只能重新输入 API Key。

页面保存的连接优先于环境变量；没有页面记录时兼容 `ANALYSIS_*` 与旧 `DEEPSEEK_*` 配置。断开后清除密文并显式停用，避免环境变量立即重新启用。已有账号授权范围仍限当前本地管理端，不进行线上部署。

## 验证范围

单元测试覆盖跨年周界、未完结周对齐、缺菜剔除、百分比与类型、时段边界、单日不能推断稳定、AES随机IV及篡改拒绝。API验证覆盖自然周归一、七日及四周输出、无未来周、连接状态不返回密钥与密文、跨来源和无效密钥输入拒绝。真实 DeepSeek 测试／成功保存仍需用户提供有效 API Key 后完成，不用假响应宣称已接通。

本次浏览器检查覆盖桌面1440px与窄屏390px、周卡片导航、单一明细表、图表定位、日期和时段切换。模拟模型响应验证自动生成、缓存复用、仅时间戳刷新不重查、切换取消及失败重试；这些结果不代表真实模型已接通。
