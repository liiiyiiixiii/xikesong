# 重量趋势与明日备料

## 在两层架构中的职责

本文描述已经实现的重量趋势与备料模型，是 [两层架构与分析设计](ARCHITECTURE.md) 中的基础分析工具。数据处理层提供经过质量检查的事实与日统计，模型计算趋势及预测；智能分析首版的 LLM Agent 调用这些能力解释证据、组织建议，不能自行编造数值或改写模型结果。当前已接入只读备料试算工具，调用 `predict` 并使用默认正则化参数 1 和 10% 余量，不保存或确认计划，也不复用历史回测调参；与每日调度的持久化预测流程分开。

现有 `Profile` 表示菜品取用趋势，不是顾客个人画像或客群分层。智能分析首版在此基础上提供整体趋势及分时段观测分析；日粒度历史不能还原时段行为，现有明日全天预测也不能直接作为晚餐时段预测。供应调整仍由管理者确认。

## 数据与模型版本

所有模型输入和结果以克为单位，算法为 `weighted-ridge-log1p-grams-v2`。独立 `weight_*` 表保存菜品、日统计、20:00 快照、模型、预测、确认、执行、评估及任务。旧 `preference_*` 与 `store` 表只保留历史，不被新系统读取。

按菜品拟合动态加权岭回归，在 `log(1＋全天取用克数)` 上建模，使用星期、当天 20:00 累计取用、前一完整日取用、上周同星期取用及对应缺失标记。模型没有人数、件数、成本或大模型输入。

历史样本权重每七天减半，每天重新拟合。全天取用需核验数据覆盖和供应状态；缺菜、缺失、未上市、未知供应和未处理异常不能当完整需求标签。有效样本不足 21 个时只显示观察中，允许管理者填写试供量。

最近七天趋势体现各菜取用量、重量占比与近期加权取用。低取用不自动解释为不喜欢；新菜、供应不足和数据不足分别标明。系统不自动下架。

## 每日时间线

- 20:00：根据当时已收到的数据生成明日预测和默认加 10% 余量的建议量。范围为模型残差形成的近似参考范围，余量是经营设置。
- 营业中：每日总结显示截至当前时间，不能称为全天最终结果。
- 闭店后：归集日总结。用于训练的取用和库存以营业截止时点为准，闭店后的清理报损继续出现在当天运营总结中，避免将清理报损再次从截止时的剩余库存扣除。全天数据不能回写为先前预测的输入，修改确认和执行记录单独保存。
- 停机后恢复：允许补生成，但记录实际生成时间和补生成标记；无法核验当时输入则标为缺失。

厨房实际备料、追加量和厨房剩余由管理者记录，秤只能直接得到上台重量变化。预测误差与执行偏离分别评估，不能把厨房实际量、秤补充量或重复报损相加。

## 合成验证

主体只接收克单位 JSON 和设备毛重，不从单次下降估算单件重量。CSV 解析与历史计件换算位于独立样例项目，人数列不进入模型。

代码中的离线回测函数按前 60 天训练、随后 15 天选择正则化参数、最后 15 天逐日测试；候选正则化参数为 0.1、1、10。每天只使用该时刻可获得的信息并更新模型。报告每菜绝对误差、整体重量加权误差和范围覆盖率。该函数不通过当前业务 API 开放；隐藏需求只能在预测完成后用于主体外的模拟缺口与剩余评估，不能进入主体的模型或 Agent 分析输入。

主体统一依据接口提供的记录训练，不提供 demo/test/live 切换。样例数据仅适用于开发环境，旧分区不会自动并入。

## 当前业务接口与 Agent 工具接入

`GET /api/preferences` 读取趋势、备料和确认。`POST /api/preferences` 仅支持 `generate`（生成）、`confirm`（确认）、`execution`（执行记录），不提供回测操作。

`POST /api/preferences/import` 使用设备凭证接收 `{"version":1,"dataset":{"catalog":[],"stores":[],"days":[]}}` 格式的克单位 JSON，不接受 CSV、`files` 或来源选项；CSV 解析与换算由样例环境负责。预测和确认数据通过 `GET /api/preferences/export` 导出为 CSV。完整协议见 [接入说明](INTEGRATION.md)。

后台任务 `/api/preferences/jobs` 只接受本地调度凭证，不向浏览器提供调度密钥。Agent 通过新增 `/api/intelligence` 编排只读工具，不改变上述 API、数据库类型或历史接口版本；详情见 [智能分析说明](INTELLIGENCE.md)。
