# 智能分析首版

入口：管理端导航“智能分析”，或 `/admin?view=intelligence`。默认本周周一至周日，提供整周、七日独立画像与连续四周对照。所有日期与时段采用北京时间。最新分析方法和页面内密钥接入见 [每日与自然周画像](WEEKLY-PORTRAITS.md)。

## 客群画像优先

首页是一周一张的卡片，点击后查看整周或周一至周日画像。详情以全部菜品矩形树图、时段柱状图、占比变化图为主，自动 AI 解读其次，全部菜品统一到一张可展开的明细表。图中点击菜品可定位明细行。图表无需模型密钥。

模型连接且本期有数据后自动解读；缓存、取消、数据口径见 [可视化客群画像](WEEKLY-PORTRAITS.md)。补充问题保持折叠，模型失败不阻碍图表查看。画像不读取模拟器隐藏偏好，不推断个人身份；缺失与真实零取用分开显示。

## 配置与使用

推荐在页面最下方填写 DeepSeek API Key，点击“连接并保存”，无需编辑文件或重启。先测试再加密保存；本地启动脚本自动准备加密主密钥。

也可继续在主体项目忽略提交的 `.env` 中设置下列服务端变量，然后重启 `npm run dev` 或 `npm run start`：

```dotenv
ANALYSIS_API_KEY=你的密钥
ANALYSIS_BASE_URL=https://api.deepseek.com
ANALYSIS_MODEL=deepseek-flash
```

默认模型及工具调用协议依据 [DeepSeek 工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)。兼容其他支持 Chat Completions 工具调用的服务，服务地址必须为 HTTPS。所有变量均由服务端读取，不使用 `VITE_` 或 `NEXT_PUBLIC_` 前缀。

如果完全没有设置 `ANALYSIS_*` 三项变量，则兼容旧 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。只要开始设置新变量，就不会继承旧服务的密钥，以免把密钥发送到不同服务。密钥不进入浏览器响应、提示词或报告；只在专用密码输入框填写，不在分析问题框填写。

选择周卡片及日期即可查看画像，模型已连接时自动生成解读；需要时展开补充提问或手动重新分析。问题及相关统计会发送至配置的模型服务。页面展示模型返回的分析及 E 编号证据，可导出包含证据的 Markdown 报告；结果只在当前页面保留，不建立历史会话库。切换页面后可重新发起分析。

没有模型密钥时禁用发起分析，显示配置说明；配置状态只表示存在密钥，不表示真实连接验证成功。鉴权、限流、网络、超时及证据引用问题会提示失败，不使用规则文案冒充模型。真实调用需使用有效密钥验证，模拟响应不代表服务已接通。

## 工具与统计边界

Agent 通过实际工具调用循环选择以下能力，所有工具只读且不接收 SQL 或写入操作：

| 工具 | 内容 | 限制 |
| --- | --- | --- |
| `daily_statistics` | 选定期间的日取用、重量占比、报损、供应状态、可比完整日均量与缺失日 | 最多31天；仅使用已可获得的日记录。部分观测量不是完整需求，缺失及未知报损不是零 |
| `current_state` | 当前余量、速率、覆盖情况和今日观测统计 | 明确标注当前时间，不代表所选历史状态，不能与同日日统计重复相加 |
| `period_statistics` | 所选日期每天指定整点时段的分钟观测汇总 | 最多7天、最近90天；北京时间左闭右开，排除当前未完成分钟。无历史完整设备配置，不能声称完整供应覆盖；日导入不可还原时段 |
| `preparation_forecast` | 调用现有 `predict` 模型做只读全天备料试算 | 以结束日20:00为截止，尚未到则前一日；默认正则化1及余量10%，不复用历史回测调参，不写入预测或计划。不能推导晚餐备料 |

新增 `weekly_portrait` 工具提供自然周、每日、时段与四周共同样本比较，采用和看板相同的计算口径。

每轮最多4个工具调用，最多5轮模型请求、8项不同成功查询；同一请求内重复查询使用缓存。单项证据最多16万字符，总证据最多26万字符，超限要求缩小范围。请求总超时90秒，用户可取消。

模型输出需引用实际返回的 `[E1]` 等证据编号；服务端验证至少存在一项成功查询和有效引用。引用检查不能证明每句话或数值都正确，用户仍应通过证据面板核对。结果区分事实、模型估计、缺口与建议；缺少客流、个人属性、收入成本、排列变更与接触记录时不能给出对应指标或因果结论。

## 接口与兼容

- `GET /api/intelligence`：返回 `configured`、`model`、`message`，不返回密钥或服务地址；禁止缓存。
- `POST /api/intelligence`：接受 `{"question":"...","startDate":"2026-10-01","endDate":"2026-10-03"}`。问题最多2000字符，日期为1至31天且不含未来日期。用户所选范围是工具查询边界；时段由模型选择整点起止并在证据中显示。
- 成功返回 `answer`、`model`、`generatedAt`（本次数据截止时间）、`scope`、`evidence`。每条证据含编号、工具、标题、参数与统计结果。400为输入错误，403为跨来源请求，503为未配置密钥，502为模型或分析失败。

沿用当前本地管理端访问方式，不新增账号授权；不进行线上发布。本接口不写数据库、不确认计划，不读取旧业务表或模拟器隐藏数据。供应调整继续由管理者通过已有备料流程确认。

## 验证

执行 `npm test`、`npx tsc --noEmit`、`npm run lint`、`npm run build`。新增测试覆盖工具循环、白名单与参数校验、超时取消前置检查、无证据和伪造引用、重复查询缓存、供应不足与缺失值、模型请求密钥边界、北京时间分钟聚合与保留期。

本地无密钥时检查配置提示、禁用按钮、输入错误和跨来源拒绝。真实密钥配置后，分别验证“哪些菜取用较多”“晚餐17至21点供应”“排列是否提高利润”三个问题：应看到实际工具证据；无分钟记录时明确数据缺失；利润问题不得凭重量或当前位置给出因果结论。真实模型、模型输出语义与服务额度必须在联调中验证，模拟响应测试不能替代这一步。

新增与周卡片并列的“整体用户画像”：基于全部有效历史的日均取用与星期收缩估计，样本不足21天标为学习中；详见 [整体画像模型](OVERALL-PORTRAIT.md)。

当前页面以“当前客群画像”为默认主视图，历史周／日画像退为次级入口。模型采用28天半衰期与星期先验，仅当当天覆盖、供应和设备新鲜度满足条件时加入当天修正；界面明确标注数据状态。详见当前画像模型说明。
