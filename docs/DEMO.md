# 完整演示与故障排查

在根目录执行 `npm ci && npm run demo`。macOS 双击入口执行相同流程。Linux 无图形桌面使用 `npm run demo -- --no-open`。

启动会先校验两套数据并构建应用，再创建 `.demo-state` 中的独立 D1，注册模拟设备并导入 33 天历史，最后启动 3D。该目录中的凭证和历史状态会保留，重复运行不会自动清空。关闭终端前使用 Ctrl+C，启动器会停止本次启动的服务。

导入使用既有维护协议：先验证批次、建立维护状态及可恢复备份，再按批次导入。中断后运行相同命令恢复；遇到不同数据集、未知凭证或不一致备份会停止，避免覆盖数据。历史界面明确展示合成数据与回放日期，后台不会伪造当天经营记录。

## 常见问题

| 表现 | 处理 |
| --- | --- |
| Node 版本错误 | 安装并选择 Node 24，重新运行根目录 `npm ci` |
| 端口被占用 | 停止自己的旧实例，或设置 `DEMO_PORT=5274 THREE_PORT=4274 npm run demo` |
| 数据摘要不匹配 | 执行 `npm run data:verify`；把修改过的解包目录移走后重新提取，不改清单绕过校验 |
| 3D 无业务数据 | 默认演示读取 `/api/demo/v1`；`mode=live` 需要独立业务服务和有效绑定 |
| 工作台要求登录 | 从本机 `.business-state/connection.json` 取得首次工作站凭证，不发布该文件 |
| AI 解读不可用 | 使用者自行配置模型密钥；基础演示与统计无需外部模型 |
| 全新实例想重新开始 | 停止服务，将 `.demo-state` 重命名为自己的私密备份目录，再启动；不要操作实际经营库 |

`npm run demo:smoke` 会检查真实 HTTP、3D 代理和暂停／继续／重播，并重置演示播放进度；仅用于本人的隔离演示。
