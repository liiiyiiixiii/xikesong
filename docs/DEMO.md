# 从干净克隆启动完整演示

要求 Node.js 24、Python 3.9+。所有命令在仓库根目录执行。

## 1. 安装与启动真实后端

```sh
npm run install:all
npm run demo
```

命令生成午餐数据、构建完整前端/API、应用数据库迁移并启动真实的本地 Worker + D1 后端。默认仅监听 `127.0.0.1:5273`；可用 DEMO_PORT 改端口。演示数据库、配置和随机秘密保存在本仓库 `.demo-state/`，与原开发库隔离，不会上传。

保持终端运行。午餐游戏可直接打开 http://127.0.0.1:5273/demo/lunch/kitchen ，支持暂停、继续、重启；这是固定种子的互动仿真，不是硬件实时数据。

## 2. 导入完整数据

另开终端，在同一仓库根目录：

```sh
npm run demo:seed
```

脚本验证并解包全部数据，配置模拟菜品/设备、建立设备凭证、进入维护、备份隔离库，通过真实 HTTP API 导入 1,188 个批次，回放预测并核对读回数据。耗时取决于机器性能，期间业务接口处于维护状态。失败保留进度和备份，重新运行可续传；不要手工清除维护状态。它拒绝自动替换其他数据集。

演示数据的凭证写入被忽略的 sample-provider/.env。此过程针对本仓库的隔离演示环境，不能用来重置已有生产数据。

完成后访问：

| 页面 | 地址 |
| --- | --- |
| 管理端 | http://127.0.0.1:5273/admin |
| 厨房端 | http://127.0.0.1:5273/kitchen |
| 完整画像 | http://127.0.0.1:5273/admin?view=intelligence |
| 午餐仿真游戏 | http://127.0.0.1:5273/demo/lunch/kitchen |

管理/厨房的统一场景回放与独立午餐游戏是两个场景，不共享时间轴。AI 文字解读需要自行配置模型密钥；模型统计与本地画像不需联网模型密钥。演示启动器不运行定时备料/归档任务；历史预测在导入时回放，常规开发启动与调度见开发指南。

## 3. 验证与离线模拟

```sh
npm run demo:smoke
npm run simulate:profile
```

前者验证前端路由与真实仿真 API 的 42 碗、暂停/继续/重启和会话一致性；会重启演示时钟。后者在无后端服务时也可计算完整日观测画像，输出模型结果及数据口径。

所有场景数据均为合成数据，未来日期也是模拟。真实硬件接入仍需遵循 red-koala/docs/INTEGRATION.md；运行真实后端不等于已完成现场硬件联调或生产部署。
