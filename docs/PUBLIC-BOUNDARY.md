# 公开与私有边界

公开库保存数据契约、通用校验、接口和测试。核心模型实现、参数、特征设计、提示词、训练或经营数据、密钥与生产部署配置应保存在另一个私有仓库及受控服务中。

`ForecastProvider` 是扩展点。公开版只注入 `unavailableForecast`。未来由私有项目实现相同接口，或通过经过鉴权的服务调用私有部署；不要把私有包、打包产物、源码映射或服务凭证加入本目录。当前没有实现该远程服务。

## 提交方式

1. 只将本目录的允许清单文件作为新的 GitHub 仓库内容。依赖目录不属于交付源码。
2. 运行 `npm ci`、`npm run check` 和 `npm run demo`。
3. 在独立目录建立全新 Git 仓库，检查暂存区文件和 diff 后再提交；不要在原项目根目录执行 `git add .` 后上传。
4. 本次交付通过 PR 将目标仓库的当前文件替换为此公开子集；合并前主分支内容保持原样。替换文件不会删除仓库已有提交历史。

根目录 `PUBLIC_FILES.json` 是显式公开文件清单。检查脚本拒绝清单之外的文件及符号链接，只忽略依赖目录和 Git 内部目录；扫描常见密钥模式。它是辅助检查，不能自动判断业务算法是否保密，也不能保证发现所有秘密。

`.gitignore` 只影响尚未跟踪的文件，不会删除历史提交里的内容。如果秘密曾被上传，应立即撤销或轮换凭证，并清理仓库历史及相关产物；删除当前文件不等于清除泄露。混淆、编码、压缩和把密钥搬到前端环境变量都不构成保密。

评审材料应说明完整产品与公开子集的差别。需要展示核心效果时，可另行提供受控演示或脱敏评测结果；本仓库不提供未经验证的准确率或性能数字。
